# Wisp 2.0.1 audit

This maintenance pass reviewed command routing and discovery, plan editing and
execution, notification proposals, microphone clarification, onboarding, saved
state, inference contention, theme rendering, and installation. Fixes retain the
reviewed capability boundary and avoid adding another command interpretation layer.

## Fixed

- **Plan lifecycle:** cancelled plans clear their token; editing cannot revive a
  consumed token. Preview and execution share validation of expiry, fingerprints,
  duplicate/conflicting steps, and registered capabilities. Helper cancellation
  and failure explanations survive in the final result.
- **Chat and notifications:** choosing a command from Commands, a clarification,
  or a notification clears previous plan progress. A failed plan cannot offer Run
  again with a spent token. Recording/transcription preserves clarification
  choices, so spoken ordinal replies still resolve locally. Late onboarding
  completion cannot close a newer panel. Commands has one main navigation entry.
- **Routing:** exact commands are matched once. A plan, its edit, or the command
  catalogue uses one discovery snapshot per request. Percentage execution requires
  no plugin scan. Dynamic actions must be registered and available before their
  helper runs; execution still checks current discovered targets.
- **Persistence:** nested state and finite numbers are validated before use, with
  recovery from a valid backup. Reads reject symlinks and special files without
  waiting, and stop at 32 MiB. Invalid primary and backup files remain intact for
  recovery. Archived files with valid pre-1970 modification times remain supported.
- **Inference:** foreground model-lock waiting has a deadline. The remaining budget
  becomes the HTTP socket timeout; background work still declines a busy lock
  immediately. This is not a hard deadline for an entire slowly streaming response.
- **Theme palette:** portraits and dream snapshots use Omarchy's active configuration
  palette. Known colors are validated, legitimate theme symlinks work, and missing,
  malformed, oversized, or special files use the existing fallback palette.
- **Installation:** replacement writes are atomic and preserve permissions and
  configuration symlinks. Backups cannot overwrite each other within the same
  second. Failed writes clean up temporary files. Reinstallation preserves an
  explicit disabled setting and explains how to enable Wisp.

## Evidence and boundaries

Run `python3 -B -m unittest discover -s . -q`, `node test_input_rhythm.js`, and
`omarchy plugin validate .`. Tests cover temporary installations, real lock
contention, recovery files and FIFOs, archived timestamps, command preflight,
plan races, and native offscreen QML interaction. Native tests use inert transports;
UI proposals do not perform desktop actions or call a model. Native tests skip
on machines without Omarchy/Quickshell; they were also run on Omarchy for this audit.

`python3 tools/benchmark_local_commands.py` measures isolated routing with an empty
discovery fixture and hard guards against model calls and desktop effects. The
25-sample run measured median 0.82 ms for an exact command, 3.13 ms for a two-step
plan, 3.14 ms for a plan with a percentage, and 3.18 ms for a pending edit. These
exclude process/UI startup and real plugin inventory, and are not desktop latency
promises.

This audit does not establish compatibility with every third-party plugin,
microphone, display, or audio device. Speech clarification is tested with a
transcription fixture; live recognition quality still needs ordinary-use feedback.
A capability's availability and result evidence remain distinct: an accepted
launch is not proof that its application became visible. General conversation
and unsupported requests can still use the optional local model.
